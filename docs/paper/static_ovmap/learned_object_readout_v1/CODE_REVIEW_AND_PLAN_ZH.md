# 源码审核与执行方案：学习式多视图对象语义读出

## 1. 本轮做什么，不做什么

源码锚点是 `30f59c1fa3d783054dc53fc6693e1fd68e8c2a6d`。本轮不再堆叠选图公式、AnyUp或SAM-V；保持FC图像/文本主干、D2的N/Q来源、G1恢复结果和全部三维实例分区，训练小型区域/对象读出网络。

实验依次回答：固定2/4/8视图是否足够；同预算可学习二维pooling是否有效；学习式多视图聚合是否必要；物理对应是否优于同参数的按视图分组；针对污染与对应的辅助监督是否有额外作用。

目前不能确认服务器上已有32个独立训练场景家族。因此数据盘点与合法材料化是P0任务，不把数据齐备当成既成事实。需要24训练、4开发、4留出家族，均与CF18家族及已知先前调参/评价家族隔离。现有26场景只做真实预测地图的回归，不参加梯度、checkpoint或训练超参数选择。

## 2. 关键源码发现与任务绑定

| 已审核事实 | 对应任务 | 风险处理 |
|---|---|---|
| `region_adapter.py`固定FC ConvNeXt与原图预处理；`clip_vis_dense`是投影前稠密张量 | 从真实FC缓存构建局部tokens和二维区域适配输入 | 不把类别分数反推成局部特征，不改旧预处理 |
| frozen视觉头先接收池化raw向量，再执行trunk.head与visual.head | 保持“raw聚合→冻结投影”的非线性顺序 | 参数冻结不等于关闭输入梯度；禁止训练路径套inference_mode |
| MaskAdapter的实际FC实现以逐位置投影后的dense产生激活图，却用raw dense加权 | 移植真实数值head与三层ConvNeXt作为强对照 | 不直接装不匹配权重；明确这是统一数据下重训架构，而非论文整套复现 |
| ScanNet项目现有loader只是把RGB resize到深度尺寸 | 新raw训练数据按官方传感器外参注册 | 不把resize当成配准；axisAlignment必须与相机一致 |
| `physical_support.py`已有去重面积与直接可见性检查 | 为同一物理site建立跨视图token组 | 不用“同数组行重复命中”替代物理对应，也不把未知当负证据 |
| 旧绑定和评价器存在分支、方法数硬编码 | 新建任务adapter，复用真实输出与有序池化内核 | 不修改原实验冻结记录，不以四场景结果代替26场景父基线 |

具体代码、blob与外部论文出处见 SOURCE_EVIDENCE.md。以上是接口事实；网络层数、损失权重、32家族划分和训练步数是本轮预先规定的设计，不宣称是已证明最优的设置。

## 3. 新方法在什么位置改变表示

原路径：区域mask → FC raw pooling → 冻结视觉投影 → 对象向量 → 类别分数。

新路径：多视图raw与投影特征 → 可学习二维区域权重 + 局部tokens → 按视图/按物理site分组 → 对象查询聚合 → 冻结视觉投影 → 新F向量。

按视图与按表面分组使用完全相同的参数结构、token、图像及训练样本，只改变分组关系。加入非线性组编码，避免形式不同却等价于同一线性平均。进一步用真实训练标注监督token是否属于目标、同一表面的跨视图一致性；不同部件不被强制相同，相邻同类实例不是错误语义类别。

本轮不加学习式修改门控。新训练场景尚无真实D2/G1旧判断；没有合理的旧错/新对训练对，不能拿GT伪造门控数据。首先确定表示能否改善，再决定是否开展后续更新决策实验。

## 4. 九种主条件

| 条件 | 目的 |
|---|---|
| D2、G1 | 继承基线 |
| FC2、FC4、FC8 | 同一视图前缀的普通识别，排除仅因多看图而涨点 |
| MA8 | 真实Mask-Adapter架构在共同训练协议下的二维强对照 |
| MV_VIEW | 判断多视图学习是否必要 |
| MV_SURFACE | 在同参数下判断三维物理对应是否必要 |
| MV_AUX | 判断针对污染/对应的辅助监督是否必要 |

所有新条件仅替换F，保留N/Q及原来源缺失规则；统一作用于有历史F、有D2分布、无raw-zero保护冲突且至少两张合格视图的已有实例。不是只挑之前能改对的16个对象。恢复owner、实例形状与未满足共同资格对象保持G1。原排名随类别重算，不能把新置信度偷偷作为实例评分。

## 5. 数据、训练与评价的实际含义

新ScanNet训练家族使用标注对象及固定三维截断/邻居污染，先建立表示能力对照，不重建OVI地图。DEV/H也是这种受控proposal识别，不等于新场景完整地图AP。这一域差异必须在报告中说明。

200类中按固定哈希留出40类，不给新适配器正类别监督；冻结模型的预训练暴露未知，因此不称整个系统从未见过这些类别。开发集只用其余160类选模；留出集读取后不改网络。所有训练GT只进入监督或受控训练proposal生成，不能进入现有26场景神经输入。

主seed17：2000步共享MA预热，四分支各2000步；复核seed29：2000步预热，MA和开发集预提名新分支各2000步。科学优化共16000步，有效batch16。两种种子分别报告，不选最好seed、不按数据集切换方法。

主回归9×26=234条/18池，复核2×26=52条/4池，共286条/22池。增加记录是种子复核，不是增加独立场景。已有26场景持续作为已曝光回归，不能宣传为未见确认。

## 6. 结论与工作量控制

首先看真实精度与机制；耗时记录但不进入晋级门槛。沿用两套数据五项均不低于G1且CF18 APall>D2、AP50≥D2的工程目标。DEV提名、回归后最佳候选、复核一致性和生产部署状态分开。没有通过者保留G1，N0部署不变。

最多3904个科学FC图像输入（32×96 +26×32），多数特征只提取一次，所有分支/seed复用。训练GT地图来自官方已有重建，不新增OVI建图、分割、AnyUp、N/Q推理。没有额外大冷测矩阵，也不为失效分支做耗时优化。原模型冻结、梯度有效、数据分离和真实整图评价是必要测试；不建设上千项审计框架。

发布分支 `research/ovimap-learned-object-readout-v1`。Codex必须真正训练/评价，输出四份报告、小型权重、配置、compact结果与复现命令，再正常push并核验完整SHA。缺数据/训练失败必须明确阻塞，不伪造完成或把父指标填给未训练分支。
