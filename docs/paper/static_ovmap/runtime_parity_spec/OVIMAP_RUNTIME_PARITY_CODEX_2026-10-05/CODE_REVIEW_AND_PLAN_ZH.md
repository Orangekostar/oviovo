# 无损运行优化与论文证据收尾：源码审核和执行拆解

## 1. 本轮定位

目标不是继续刷新的AP，也不是要求G1追平U2的6.61秒，而是回答：
**保持最新v2的选帧、mask、区域向量、类别、实例支持及官方评分结果不变，
能否减少无效投射、重复加载与运行开销？**

当前Table3的45.58／45.63秒为用户实测汇报。准备本包时，远端分支仍为
`77335848b776d99ffb4ca772e33fa391d9fd8e5e`；远端AREA_FALLBACK_V2_RESULTS.md
读取失败，Files也未找到其当前可读副本。因此已审核的是旧执行链和之前的
实验规格，**没有假装审核了未取得的v2备用池化公式**。Codex必须在服务器绑定
实际v2及最新计时产物后再开发；不能拿旧空mask失败分支当作准确性参照。

## 3. 对上一版口头建议的修正

1. **不直接把“bbox投影＋2像素”宣称为严格几何等价。** 浮点、非精确旋转、
   近裁剪面都可能影响边界，必须保守回退整图，并对26场景实际选帧mask验证。
2. **不做会改变求和或卷积路径的大批处理。** 本轮只共享加载与转移，神经编码
   保持每次一图、每个区域原算子；批量重写pooling留给后续而非暗中并入。
3. **不再要求新旧request ID逐字相同。** 它包含代码身份，正确加速也会改变；
   真正必须相同的是几何、视图、mask、类别和评分内容。
4. **不拿历史U2时间直接除新G1时间。** 正式八场景两轮包含重新测得的U2控制和
   G1参照；原45秒只作为历史上下文。
5. **不把副本/审计改到计时外来制造加速。** 两实现共享相同新适配范围，必要的
   输入、输出与执行记录都计入；GPU service与wall time分开，不重复相加。

## 4. 实验范围和成本

| 阶段 | 上限 | 作用 |
|---|---:|---|
| pilot：room0、office1，R0–R3，G1，每种两次 | 16次冷恢复 | 分段计时＋实现选择，profile包含在此 |
| 固定26场景的CPU投影/内容验证 | 最多52次投影过程 | 优化版每场一次；原诊断缺失才补参考一次 |
| 最终8场景：U2、参考G1、选定G1、选定G3，每种两次 | 64次冷恢复 | 同设备、倒序平衡，真实调用及预测一致性 |
| 无加速候选保留时 | 最终48次替代64次 | 只测U2、参考G1、参考G3，不机械重复别名 |
| 新建地图／训练／新模型／Native crop／分割推理 | 0 | 不扩任务 |
| 表7类证据 | 复用A2/A5/A3 | 两个benchmark均来自同一v2表2 |

普通冷恢复调用最多80次，另最多4次有原因的环境故障重试。不是80张地图，也
不是80种科学方法；已有172条精度结果、14个池化仅在内容一致时按明确来源复用。
新增GPU计算为实际FC冷测，不能再报“整轮0推理”。CF18只做CPU视图与缓存导出
一致性，**不据此宣布CF18优化后GPU耗时已实测**。

## 5. 如何选“最好版本”

冻结模型、D2、G1/G3规则和v2fallback。只在两个pilot上按完全相同预测约束，
选择最快实现；与最快相差3%以内优先更简单的实现。选好后固定，再测完整八场。
最终总时间降低至少5%为预定的工程目标，并非统计显著性门槛。不根据CF18的AP、
按场景或对象切换实现。不达目标也正常发布参照与负结果，不继续无限调试到涨点。

## 6. 论文如何使用

- 主文仍保留三表；表1/2精度不变，表3换成同一新系列的准确性复用与时间。
- 补充S7用Native/FC-only/D2、共同G1恢复三行解释已有语义来源；这不是严格
  骨干消融，不能据此宣称已隔离mask pooling或跨骨干通用性。
- 补充S8解释U2、参考G1、优化G1的候选/几何、投影视图、加载、FC识别、输出和
  总耗时，独立保留GPU事件时间。不要移植OVI表8的在线线程/跳帧结论。
- 优化不会改变“G1与U2 AP相当、CF18恢复仍有取舍”的科学事实，只可能改善
  性能—时间的取舍。
