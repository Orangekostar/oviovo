## 1. 这轮任务的目标不是继续堆模块

M2_CAL已经显示出冻结参数迁移时的平均改善，但还未证明三路来源、完整分布和三个温度分别必要。这轮允许实验否定原设计，并明确简化方向。部署方案不自动变更。

| 审稿疑问 | 必做实验 | 可得出的结论边界 |
|---|---|---|
| 三路是不是多余？ | N0+Q、N0+S2、Q+S2 | 哪一路提供额外信息；不是证明完全去掉N0建图成本 |
| 是软分布起作用还是投票？ | 固定规则硬投票 | 不以同名模型的回退结果凑票 |
| CAL是不是只把概率变尖？ | 统一0.01、共享拟合温度、原分源温度 | 是否真的需要分源校准 |
| N0和Q/S2分数定义不同，是否造成隐含权重？ | N0改余弦、固定温度；再仅重新校准N0 | 分开分数表达与适配温度，不把两者混成一项 |
| Q是否只是额外计算？ | 用COMBINE、三种固定种子的随机查询替换Q | 固定其余两路、编码器、预算上限与融合规则 |
| 提升是否依赖特殊评测处理？ | 固定排名／官方按当前类别重算排名；逐场景均值／官方整数据集汇总 | 四种口径分别列出，不能冒充彼此 |
| 概率是否更可靠？ | 同对象集NLL/Brier/ECE和覆盖率 | AP提升不能替代概率校准证据 |
| 能否泛化到不同词表或新场景？ | 固定图像特征的文本压力测试；有真实未见数据时一次冻结确认 | 不把旧Replica或旧CONFIRM重新称为盲测 |

### 公式层面的观察与实验结论要分开

N0的canonical-relative分数满足`min_k sigmoid(s(c)-a_k)=sigmoid(s(c)-max_k a_k)`。它通常不改变单路最高类别，却会改变类别差距，进而影响融合。这个公式证明了“存在影响途径”，没有证明它就是过去上涨的全部原因。

同样，单文本softmax恒为1，所以当前M2公式本身不能直接充当任意单文本检索评分。本轮只检验词表/提示变化，不临时发明检索头，并在贡献账本中保留这一能力边界。

## 3. 核心矩阵：七类问题，八个新配置

| ID | 内容 | 与原讨论相比的细化 |
|---|---|---|
| A1 | N0+Q | 原分源温度，不重搜权重 |
| A2 | N0+S2 | 同上 |
| A3 | Q+S2 | 两路均无真实证据时输出class0，不暗中用N0当第三来源；整图照常承担漏检 |
| A4 | 硬投票 | 并列先用仍实际参与且处于并列集合的N0，否则按固定类别顺序 |
| A5 | 三路统一0.01 | 检验共同锐化 |
| A6 | 三路共享一个拟合温度 | 与分源拟合相同的单源NLL目标和场景权重 |
| A7a | 仅N0换为余弦、保留旧温度 | 固定参数的分数表达影响 |
| A7b | 同A7a，仅重拟合N0温度 | 避免因尺度适配不足而错误否定余弦表示 |

另保留5个实测控制：N0、Q_GAIN、S_SIGLIP2_AREA、M2_RAW、M2_CAL。2个ScanNet CAL与8个Replica，共130条scene-method预测记录；两个排名视图为260条记录。Replica官方汇总另有26条method-rank记录。**这些是记录数，不是独立试验次数，也不是图像推理次数。**

A3只删掉N0语义证据，几何、实例集合和固定rank仍来自N0，因此不能将它宣称为完全无原生语义基础成本的系统。另报告真实三路都可用的共同对象集，避免用改变覆盖率替代机制解释。

## 5. 查询对照和计算控制

中间来源分别用Q_GAIN、Q_COMBINE、三个种子随机策略。全部在当前帧的相同技术候选上工作，使用原生编码器、同B200上限与同一多视图聚合；并输出单路与RAW/CAL融合。替换策略自己的温度只在CAL拟合，N0/S2不动。

主查询对照覆盖10场景，总上限10,000次逻辑原生请求（含可复用的旧控制）；新物理前向只补精确缓存缺口，不等于一定新增10,000次。原生基础捕获和静态S2不是这部分B200预算里的免费数据。

只有CAL中Q_GAIN融合同时超过COMBINE和三种子随机均值的AP、且mIoU不降，才在Replica8增加Q_GAIN/COMBINE的B100/B400曲线。额外逻辑请求上限8,000；固定B200温度和Q权重，不截断别的预算的最终状态，不按预算调模型。

成本分开记：原生建图公共成本、逐方法逻辑来源成本、可证明完全相同操作的依赖并集、本轮真实物理前向。不得把缓存算成零成本方法，也不因两个来源用了相似视图就随意去重。

## 8. 审核与验收边界

交付前的包审核检查Markdown/JSON参数一致、方法命名/数量、源引用、数据角色、拟合权限、预算公式、发布目录和ZIP完整性；它**不是**新算法实验通过，也不是目标服务器资产读取成功。机器审核结果写入`PACKAGE_AUDIT.json`。

Codex侧只做10组直接相关的紧凑fixture检查、一次真实历史样本/场景对齐和一次官方pool/导出对齐。不要用测试数替代实验，也不要跑全仓动态回归或GPU压力测试。

最终上传：新代码、实际配置、标量拟合、小结果、对象账本、`M2_REVIEWER_RESULTS.md`、`M2_REVIEWER_HANDOFF.md`和`M2_CLAIM_LEDGER.md`。基础模型和大图像不入Git。普通push后必须核对本地HEAD和远端完整SHA；未成功不得写`PUSH_VERIFIED`。
