## 2. 数据调用链：应该复用什么，不应该调用什么

**E/R原四格链**：COMPACT `resolved_inputs.json` → per-scene context → A0 native payload 与 N/Q/F → AREA `experiment.json / predictions / evaluation` → `CT_A0_NATIVE/CT_A1_E/CT_A2_R/CT_A3_ER`。后续 EV/IR/FG 名称只是引用关系，仍须 payload 身份证明。A5同时启用F-only和恢复，所以不是裸F对照。

**E新消融链**：验证历史scores/temperature/availability → 只重组概率 → 固定A0 owner与geometry → 原native_ranks → 锁定输出 → 原SceneEvaluator＋ordered pool。基础语义读出中的全缺源fallback必须显式标注，不能用native label偷补纯F。

**普通权重选模链**：BB四开发scene的BB00_NATIVE真实输入 → 全15配置预测锁 → 开发官方池 → 唯一weight_lock → 26scene回归。不存在完整开发输入时不选权重，不挪用对象DEV或回归标签。

**S结构链**：原训练step1000 DEV输出 → matched初始化/draw检查 → 同budget FG1/FG2结果；已选FG2权重→原七键→五次独立valid-slot token联合置换。前者比较结构包，后者只是推理依赖诊断，不能互相取代。

**S×融合链**：LR的LR04_FC_8 scores＋FG的两selected head scores → 固定G1与eligible域 → 新J0/J1/J2的F-only → 与已有D2三配置四格。历史F、FC8和FG2是不同来源状态，不得混名。

**评分链**：实际receipt中的上游evaluator/GT/projection → SceneEvaluator → assign_instances_for_scan → trace_released_matches → scene receipts → released_pool_with_classes。新调度只替换任务列表，不替换数值内核；scorer namespace初始化和已有兼容层保留。

**统计链**：已锁定matches/trace/confusion → 同原evaluate_matches的聚类重采样 → official算子AP和语义confusion指标。原pool会用scene键去重，因此不能直接传重复scene；也不能抽样scene AP均值。

**归因对象链**：旧conveyor提供最大几何IoU参考 → 新的互斥错误路径。最大IoU可能多对一；一对一几何配对另算；官方TP/FP由原trace提取。这三个列组永不互相命名。

**运行边界**：不能调用旧bind/fixed_spec/train/all；这些函数带有旧任务分支、stage、286/11/22计数与发布约束。复制小配置的原字节，创建新binding与新输出；只借用纯数值接口。
