版本：2026-09-20-v1。审核对象是任务规格与交付包，不是已经实现的新算法。本次未下载/加载新视觉权重、未训练、未运行新benchmark、未改动远端仓库。

## 1. 根据源码做出的关键修订

| 核查发现 | 最终指令的处理 | 对应文件 |

## 2. 工作量与范围审核

首版固定12个独立开发家族（8/2/2）与2个确认家族，而不是原草案最大24+4。不根据实验分数扩场景或改变划分。独立数据不足时仍要求完成代码与可运行直接对照，不能用Room0的不同帧/crop替代缺失的独立学习验证。

S至多5个直接读出+3个小头，与N0同域比较；G只有3个固定pool条件；Q主预算只有4个条件。开发主矩阵每个SELECT场景最多16行（含N0），两场景最多32行；精确相同payload允许少于该数目的实际评测，但不能删逻辑记录。CAL阈值是在既有预测建议上切换，无需重做大模型前向。通过固定选择条件才增加至多4行Q预算曲线/场景、至多2种组合。确认每场景至多4行。

新模态开销允许但有账本和上限：原生重放、必要的缺失CropFormer缓存、SigLIP2/WOW、三种小头学习。不会同时部署整套LEGO/GeoGuide/OVRCOAT/APPLE/NBV-Gym。已有大模型冻结。

训练和验证不以测试数量作为目标。只有接口/身份、真实区域输入、C++导出、因果前缀、预算和发布版trace这些相关检查。负科学结果不自动触发重跑旧矩阵或无关动态CROVE回归。

## 3. 选模与发布闭环审核

| 决策 | 依据数据 | 审核结论 |
|---|---|---|
| 模型来源与可运行性 | 实际权重/config/code/处理器，不看accuracy | 缺失候选单独阻塞，不能换普通InternVL冒充WOW |
| 备选教师、head checkpoint、采用阈值 | CAL | 固定有限集合、固定tie-break，无SELECT/CONFIRM选模型 |
| 是否保留模块与组合 | SELECT | 同域强控制、实际干预、纠正与损坏一起计；零干预非有效创新 |
| 确认效果 | 预先冻结的CONFIRM | 无候选不强行确认；失败不在确认集回调参数 |
| GitHub上传 | 实际git push及ls-remote比对 | 代码、小权重、小结果、两个MD均在提交集合，不能只传计划 |

## 4. 不可消除但已明确规定处理方式的未知项

没有声称目标服务器已具备12个独立开发场景、已完成WOW加载、已保存全部原生叶片历史，或三模块必然涨点。规格规定了资源定位顺序、不可替代的身份验证、分支级阻塞状态以及其余工作继续执行/提交的行为。

“全部开发”指规定模块与接口必须实现；“实验完成”仅指依赖满足且真实运行的单元。资产缺失不能被写成科学负结果；代码完成也不能写成三项创新已经有效。最终报告必须分开工程、实测、科学、确认、发布五类状态。
