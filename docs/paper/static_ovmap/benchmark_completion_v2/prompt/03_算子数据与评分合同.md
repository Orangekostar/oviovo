## B. 校准算子

设单位基础向量b、适配向量z、冻结文本行矩阵T，类别轴valid_ids；原分数s_b,s_z必须来自相同模型/词表。base_mask由训练base语义集合确定，绝不取当前对象真实类别。

### B1. RAW和类别偏置

`RAW(gamma)=s_z-gamma*base_mask`。gamma使用原余弦单位；不先除温度再减gamma，不从概率减gamma。unknown不以填零向量伪造有效输出。

### B2. CAP

在FP64中算 `c=clip(sum(b*z),-1,1)`、`theta=acos(c)`。theta不大于tau则保留z；超过时：

`direction=(z-c*b)/norm(z-c*b)`，`z_cap=cos(tau)*b+sin(tau)*direction`。

当需要裁剪且切向范数<1e-10，回退b并记antipodal_fallback。返回向量恢复z的原FP32；不进行第二次文本归一化。tau180直接保留z。CAP候选分数按原A实现重新`z_cap @ T.T`；它与源分数允许浮点级差异，不能仅凭accuracy相同声明bitwise alias。

### B3. MIX

`(1-alpha)*s_b+alpha*s_z-gamma*base_mask`，不归一化。alpha0/1分别复制对应原分数，保持源精度。两端defined只需相应源；内部alpha要求两源均有效。

### B4. NMIX（新增）

`w=(1-alpha)*b+alpha*z`；alpha0/1直接返回b/z对应原分数，内部alpha用`w/norm(w)`与原T匹配再减gamma。内部w范数≤1e-12时返回b，记录degenerate_nmix_fallback；不用NaN或随机方向。使用FP64完成范数/组合后恢复FP32向量，矩阵分数FP32。没有任何可学习参数。

A的公平候选域：
- alpha=0,.25,.5,.75,1；tau=5,10,20,30,180度；
- gamma=−.5,−.25,−.1,−.05,−.025,0,.025,.05,.1,.25,.5；
- MIX/CAP/NMIX三个并集，各55，非三重笛卡尔积。

每模型/seed165候选，4模型×2seed×165＋静态FC11=1331逻辑行。原MV两seed110候选可通过精确meta、对象key及prediction数组复用；不要求重复生成其220行。candidate logical rows、real CPU score passes、cache hits分别统计。

### B5. defined与指标

调用E03 predictions/recognition，未知预测ID=0；正样本类别从targets产生，不能把未出现类别填0。主指标：
`B=mean_{positive base classes} accuracy_c`，`N=mean_{positive novel classes} accuracy_c`，`H=2BN/(B+N)`；一组无样本为null，两组存在但均0则H=0。H_micro另算，不能用普通Top1冒充。

calibration窗口：已定义z却无b时RAW/γ-only可以预测、需要anchor的CAP/NMIX不能伪造b。所有方法同一原件全分母保留，报告defined差异。本轮既有9unsupported仍计错。新标准输入应保证MV有输入时b也存在；若不成立是数据/模型实现错误。

### B6. 选择与聚合

LOFO以原physical family拆分，另11家族seed17选参数，留家族两seed统一应用。选择排序：H→min(B,N)→B，容差1e-10；然后较少非恒等操作（插值alpha1/角度tau180算0、gamma0算0），最后candidate_id字典序。规范candidate_id由kind、原强度值和带符号gamma组成，JSON同时保存数值以免字符串解析歧义。

每fold选中配方与全部候选开发指标保存；OOF拼回N原件才算总macro。两个seed结果独立算再平均，不能把558行拼成独立数据。若一个fold开发集一组空，无合法选择则记undefined并阻塞该OOF汇总，不借用该fold测试标签选参。

额外全局简单对照：每kind在整个已曝光CONF12 seed17独立从55格选一个固定配方，之后迁移到benchmark不再选参。CAP10/γ.025主方法配方不跟着这次赢家变化。必须明确这不是新novel-label-free模型选择。

## C. 模型与最小实际输入

现有模型加载用E07 `load_export`。`profiles['MV_ATTN:seed17:matched1000']`等解析原gzip/XOR model-only权重。state method/step/seed与manifest核对，不下载新的同名模型顶替。

MV forward只使用区域向量进入网络（E25）。新区域-only接口：
```
RegionInput:
  fc_vectors: float32 [V,768]
  view_valid: bool [V]
  frame_ids: int64 [V]
  local_raw: float32 [V,0,1536]
  local_unit: float32 [V,0,768]
  metadata: float32 [V,0,8]
  local_valid: bool [V,0]
```
V≤8，不添加token、不改position order，不使用GT。空局部数组仅表明MV不请求这一信息。b由原FrozenFCBase精确计算；z由原MV，eta原推理0.5，不缩向量、不改attention。

两个真实缓存对象上比较完整7张量forward与region-onlyforward，b/z差异≤1e-6且top1一致；若GPU内核原非确定性导致1e-6不能保持，使用父runner的FP32、TF32关闭、math SDP配置后复核一次。仍不等价则禁用优化，不能改参考数。

对旧对象直接读SparseInputs实际fc_vectors，不重复局部投影。对新对象：E14 choose_views按最大mask锚点＋新增可见面积选择最多8视图；读取真正RGB、mask与resize/pad描述符，用E13中signed_mask和原region_vector生成FC区域向量。若只需raw网格，不为MV存不使用的projected/local grids。不得改变CLIP/FC骨干、裁剪/掩码读出、FP32精度来节约计算。

## D. SceneBundle：新增标准场景接口

新建 `SceneBundle` 序列化为JSON＋分片NPZ，最小字段如下。所有目录路径是运行时真实路径，代码不得在缺数据时造占位数组。

```
benchmark, scene_id, family_id, protocol_id
source_geometry: {xyz_path, faces_path?, coordinate_system, native_unit}
evaluation_geometry: {xyz_path, vertex_count, vertex_order_identity}
frames: [{frame_id, rgb_path, depth_path/depth_scale, pose_c2w,
          color_intrinsics, depth_intrinsics, RGBD_registration, transforms}]
frame_plan: {rule, finite_pose_frame_ids, chosen_frame_ids}
instances: [{owner_id, immutable_mask_indices_in_source_geometry, geometry_identity,
             views, available_F, source_N?, source_Q?, source_static_F?}]
text_sources: {N:{ids,names,features,template}, Q:{...}, F:{...}}
source_provenance: {native_capture, deferred_metadata, model_files, Q_GAIN_checkpoint,
                    learned_data_roles, actual_attempts, actual_encoder_content_ids}
eval_sidecar: {path, access_phase:'score_only'}
```

约束：
1. 在构造几何/实例/观测时只消费坐标、深度、RGB、预测mask，GT语义类别仅score-sidecar读取。官方原始mesh的xyz可用于投影，不利用GT owner补mask。
2. Ours的source帧计划均匀采样最多200个finite-pose帧。k=min(200,n)，索引floor(j(n−1)/(k−1))，k=1时0；先排序、去重，记录真实frameID。F从该计划中选择≤8。外部方法保留自己的paper/default策略并报告，不称全表所有方法输入相同。
3. 新标准native分区不含G1恢复R；原对象全部进入registry。没有合格view可abstain，不因GT或预测难度移除owner。
4. 原OVI source capture/deferredmetadata由其实际程序产生；N/Q新输入需E20/E21语义适配器。仅改scene名称无法得到合法N/Q；缺capture是明确依赖，不能Q=N或用旧scene分数替代。
5. 不同语义源可以是不同模型空间，必须各自对同一目标类别名字编码，然后按类别ID重排分数；不对不同模型embedding求均值。

## E. 四格定义与缺源规则

设F0=s(z)，F1=s(CAP10(b,z))−.025×base_mask。定义：
- U00：argmax(F0)；
- U01：argmax(F1)；
- U10：D2(N,Q,F0)；
- U11：D2(N,Q,F1)。

D2调用E15：每路先以自身正温度softmax，N/Q可用者均值为一组，F为一组，然后可用组等权并归一化。偏置在F温度之前，不能把.025从最终概率减掉。全部数组保持原类别轴。

F不可用：U00/U01=unknown0；U10/U11仅融合现有N/Q。NQ不可用而F存在：U10等同U00、U11等同U01。全缺为0。所有case记录真实可用性，不创建虚拟F向量。两seedF网络不同，N/Q源内容共享，不能当额外独立scenes。

**不能复用E10来导出GLOBAL四格**：E10只允许改旧eligible且禁止恢复对象。GLOBAL使用新的 `PredictionManifest`，immutable mask域覆盖全部原native owners；source toggle不依赖历史sem labels。旧L00–L11单独保留E10恰当限制，caption明确局部作用。

标准导出每owner一个top1合法类别，confidence=1.0；unknown或官方排除stuff不写为可评分预测但要统计。GT完整原始分母不动。相同mask/labels/confidence才可复用评分。类offset在top1决定之前，因此可能改变AP；不能在“每proposal对全部类别都输出”协议下用同一结论，因为常数偏置不改类内排序。

额外诊断对同一b/z计算固定γ-only、CAP-only及全局开发锁定CAP/MIX/NMIX；不额外运行head。这些可以做T3对象条件识别而不必再跑所有候选的完整AP。标准AP正式只需要U四格与四baseline；额外AP另列任务而非隐性增加。

## F. 标签、投影与统计

ScanNet200采用作者/官方类ID映射，文本可能包含200类，实例评分按官方合法实例类（常用198）过滤；精确列表从锁定evaluator导入，不手写序号。Replica48名称、ID、GT点序都来自同一作者release。旧51维分数只能在确实一一对应目标名字时按列选择，再按新48文本竞争**重新预测并评分**，不能复制旧AP。

训练base映射顺序：相同语义ID体系的官方mapping > 官方canonical name casefold/空格/标点规范化等值 > 已有有出处alias。多义/冲突必须记unresolved，禁止按嵌入余弦或测试GT分布自动归为base。未解决会影响γ时，全CAP+γ该benchmark仍缺失；可报告另名CAP-only诊断，不假装U11已完成。

预测source points到evaluation points只采用冻结几何映射：相同domain优先identity；否则在相同坐标系进行确定性nearest-neighbor，使用作者协议的有效距离限制（若作者没有限制则不自造标签相关阈值），记录未匹配/重复映射。类别/GT不进入几何映射。源有重叠proposal时保留重叠，不能以argmaxowner强制互斥。

标准共同评分器必须兼容官方预测格式与所有baseline的mask索引域。用官方第一scene调用核对一次与官方入口结果一致，再批量评分。每方法原confidence保持，Ours标准confidence是明确方法配置，不称为原OVI排名复现。

AP汇总使用完整锁定scene集合的matches调用evaluate_matches/compute_averages。按family bootstrap时所有capture一起重采样，重复scene与prediction filename同时namespace，避免dict覆盖。每个seed单独汇总，每draw再平均差值，记录有效draw数量。

T3的新真实提案诊断可以使用与预测类别无关的几何匹配：先构造IoU>0.5的预测/GT图，最大基数优先、再最大总IoU、再owner/GT ID稳定破同；六种后处理共享这组匹配。它是**matched-proposal conditional recognition**，配合S6全GT召回，不叫全场景对象准确率。未匹配的proposal和漏检GT仍完整进入T1官方AP。不得按各方法预测类别重新挑匹配以提高B/N/H。
