# 数据、评分、条件执行与发布接口

## 1. A读数据：不要误解公开压缩格式
1. 读STRUCT_ROOT/source_binding、role_lock、class_split、GT/input_lock、GT/prediction_lock。
2. pointer→record→arrays读full200_cosines/embeddings/defined；columns位于全局prediction_lock。每object最多一个记录，shape与columns/四条件一致。
3. 缺原score NPZ时，BASE公开`artifacts/static_ovmap/structure_confirmation_v1/scores/manifest.json.gz`，用kind=GT及record_metadata.key连接到records下的GT预测锁；FP32用prediction_codec.decode，非普通gzip JSON。导出REG FP64不能拿来替代GT FP32。
4. 公开scores没有embedding；若原embedding不可恢复，用已验weights profile和原七键cache补。没有原raw或sparse则A_vectors PARTIAL，不重新编码，不用text pseudo inverse。
5. 所有指向旧`/mnt/shared/...`的路径只经已验证path_map解析；父文件只读。

A不做新的全地图评分，原REAL稀疏分数仅补充描述来源；避免在16个高质量匹配对象上反复优化。

## 2. 关键字段 schema

`ObjectScores`: key, scene, family, target_class_id, class_role, condition, method, seed, profile, step, prefix, valid_ids, scores[200], defined, vector_path(optional), source_id。
`class_role`: A使用OLD_BASE/OLD_NOVEL；B/C使用CORE/PSEUDO/FINAL_NOVEL，不共享同名base布尔导致混淆。
`MetricSet`: B_macro,N_macro,H_macro,B_micro,N_micro,H_micro,ordinary_all,balanced_all,per_class,per_family,support,undefined；N在B指PSEUDO、C主表指FINAL_NOVEL，显式role_pair字段。
`Recipe`: source_method, source_step, seed17_locked, mode(MIX|CAP|IDENTITY), alpha|null, gamma, angle_cap|null, penalized_class_ids, candidate_id。
`Output`: normalized_embedding(optional), cosine_scores, decision_scores_after_recipe, prediction, defined, initial_center, pre_unit_output, diagnostics。后处理gamma不再是纯cosine，必须另存decision_scores，禁止命名raw_cosines。

## 3. B旧地图：纯F与D2分开

原回归输入由FG/LR regression manifest和features读取。不可调用硬编码286/572条的旧全调度。复用 `frozen_fc_routing.prediction.build_predictions` 中的纯过程、`disagreement_query.outputs.build_payload`、`paired_evidence_study.residuals.pool/simple_dependence` 和原partition evaluator。
14逻辑槽=RAW 3方法×2seed、POST3×2seed、BFC、BC0。各槽固定selected，prefix8。
- F_ONLY_FIXED_ELIGIBLE：新decision_scores argmax用于原eligible；未eligible按本轮BFC地图参照保持。
- PARENT_D2_FIXED_ELIGIBLE：N/Q原score不动；把同尺度的新F decision_scores送原温度和PE_D2_GROUPED；未eligible、恢复支持、背景保持原规则。
校准gamma会改变F分布，应明确是“新读出+固定校准接入”，不是单纯embedding原样替换。RAW无gamma的表独立保留。
Replica必须用原51类文本和valid_ids，gamma类指示通过规范类名与原ScanNet200映射建立；无法唯一映射的Replica类不扣bias并登记。不得因为前向训练使用200类就将51类评分空间改成200。CF18沿200。
BFC与历史FG0_FC8先做2个对象数值核对，score/top1差异需查明缓存或文本，不擅自更换旧baseline。
14×2×26=728逻辑行、56池。exact label/owner/rank/scorer同一才可alias，不能只因为AP相同。新增模型向量只算一次，各recipe复用。
如果CORE/PSEUDO类别约束使原训练意义改变，结果必须写NEW_CORE152_PROTOCOL，不与旧S+3pp描述作同监督比较。

## 4. C新家族：先锁列表，再获取，再标签无关输入

新family列表来自旧固定官方train文件，读取有限exposure索引排除所有已知使用家族，尤其STRUCT CONF12、原H/H2。新family hash和最低capture见02，12个名字先锁。路径存在不等于授权；读取已有ScanNet acquisition authority。缺任一名单文件不改名、不按novel类补样本。
获取60个原件（12×5 suffix）采用现有授权layout和有限transfer，最多2并发、每文件一次重试，断点保留。先估算download+cache+20GiB，超限则C_PARTIAL_RESOURCE，不删用户旧缓存。
提供的未对齐mesh、raw sensor、depth/color校准保持一致。SensorReader不把无效pose填identity，不把标注axis alignment只用于一个模态。

## 5. 更密集但仍受限的真实提案

沿父模型资产/SAM2 commit和AMG参数。只修改新的任务worker的固定retained cap=32；不得改原preservation_routing/sam2_worker.py，因为其他历史任务依赖它。
每家族候选frame96上限、AMG seed12、索引floor(j*(n-1)/11)去重；使用前代已修复的SAM链接库隔离。图最多144，hook记录image_encoder实际调用、decoder batches。
每mask保留predicted_iou/stability/pixels/digest与rank顺序；lift到可见source mesh rows。完全相同source_rows可合并为同一提案，附全部来源；有重叠但不完全相同者不得用GT合并。没有新增cross-view merge算法或oracle union。
每proposal固定支持→mask重投影→coverage-first最多8V→同样64slot输入；无两有效view仍写supported=false和unknown，支持分母包括所有lift失败/稀疏提案。
新提案数量增加只是测量覆盖尝试，不承诺更完整/更正确。新REAL AP不与上轮4seed×16mask的绝对AP作方法进步对比。

## 6. 预测与GT屏障

锁模型→锁角色→获取原件→mesh/sensor几何→SAM+真实input_lock→FC shared features（复用S16的capture_frame数值，不调用旧FrozenFC.capture的3904图估算）→全12场景、14槽REAL predictions锁→才读annotation匹配。
读取文件名/下载字节可在前，解析GT内容不得在真实预测前。新GT诊断随后构造，每family先匿名hash截取最多64合法实例，再做可见性检查，不因无支持替换第65个。
GT诊断four条件与父方法相同；原GT几何仅诊断，不能进入真实proposal流程。
RAW/POST/static与matched1000列分别保存。最多GT每对象48columns：14selected×3prefix+6matched×1；REAL只14selected×8V。主声明没有new online map，newNQ=0。

## 7. 评价主表与缺类

REAL：全GT场景、全固定proposal，constant1 confidence。未知标签不进官方预测txt但算unknown分母，不能从可用统计分母移除。重复/overlap原matcher处理；集合支持来自同source rows，无GT筛选。官方APall/AP50/AP25每seed独立pool后求均值。
GT：original cleanTop1、类均衡Top1、H_macro_CORE_FINAL为主要实证；PSEUDO单列；H_micro、A/M/C辅助。四条件指标原件家族相关，不能当四倍样本。NLL152只用于CORE正样本；PSEUDO、FINAL CE152=null，其NLL200可定义。全类200竞争不改变。
无class正样本null，支持class集合每表公开；不能按不同方法定义不同GT分母。categorybalanced不是按familybalanced。
模型matched1000的6列只做GT结构诊断，不替代各方法post合理选模表。若不同postselectedstep也要列明，不把差值当纯同step因果份额。

## 8. C统计与结论

只做四对：E_RAW−R_RAW，E_RAW−FREE_RAW，E_POST−SIMPLE_STAR，E_RAW−BC0。每对1000个family bootstrap seed4817，四组共4000抽样集合；两个seed同时抽入相同family，各自评价再平均。GT主口径selected raw/post；matched1000额外点估计，不搜更有利区间。
每抽到重复family，其场景和预测文件名使用独立namespace，调用既有官方evaluate_matches/compute_averages；不可平均scene AP。类缺失与defined draws报告。
没有GT新假设通过就不声称“证明保持泛化”：E需超过简单对照、同半径对照且不只是极端牺牲CORE；最终报告各项而不是只给H。
“至少40个IoU>.5唯一GT/20novel”是覆盖参考，低于时统计仍照常但外推LIMITED，不能仅因分数好就解除。

## 9. 发布事务和退出状态

合法执行终态：COMPLETE_A_NO_RESIDUAL_SIGNAL、COMPLETE_B_NO_ADVANTAGE、COMPLETE_ABC（科学结论另字段），都可exit0。依赖/数值故障PARTIAL_*须非零科学退出，外层仍写报告并尽力发布。不可将C未激活与C依赖失败都写SKIPPED。
C1固定研究代码/模型/结果，正常push核对；C2仅C1收据和交接永久链接。C2外部收据与resume真实计数写OUT，不陷入自引用SHA循环。原publication.py有旧SCOPES/256MiB/旧task常量，必须新任务实现事务，不直接调用旧run。
只做一次scope/path/size检查。终态resume检查当前任务源/锁与直接已消费文件，不全量扫描所有历史模型文件；若实际被消费源变了就阻塞本任务恢复，不重跑父历史全部审计。

## 10. 数量核算

C的GT最坏head调用为768原件×4条件×(14selected×3prefix+6matched1000)=147456；REAL最多4608×14=64512，合计211968，故C硬上限220000（可因相同checkpoint/输入alias降低）。REG 1436个继承对象×最多14向量槽=20104，预算24000。若实际原manifest对象更多，先核对预算，不裁对象分母。B训练名义384000＋DEV最多8280＋200次重放×32=398680，低于420000上限。

数学凸包/半径可行性仅指RAW归一化前y。POST分数混合、gamma校准后的decision_scores没有同一凸包或半径保证，必须独立标明；不能把RAW约束的性质自动转移到POST类别结果。
