## 二、本次审核补出的接入问题

| 已核实问题 | 为什么会让实验失真 | 最终处理 |
|---|---|---|
| `native_crops()`要求union包含完整target | SAM修边可能合理地删除错误区域；把结果OR回target会抹掉修改 | 单独实现recognition-mask裁剪，保留原请求验证，不全局放松旧接口。[L02/L03] |
| Q原特征是六crop的原始均值，并保留面积权重和最终谱系 | 改成单位向量中位数时，同时改变了归一化；还可能错误复活旧观测 | 固定paid/retained记录，增加RAW_EQ与UNIT_EQ对照，再测GMED。[L01/L09] |
| 新模型不在旧白名单，且输出维度不同 | 只改配置名字会调用错误模型或把旧文本特征接给新编码器 | 独立worker/source接口，维度来自实际模型，图文空间和真实可用性单列。[L03/L04] |
| 原裁剪存在窄图像HWC适配历史问题 | 自动维度猜测可能把颜色轴当空间轴 | 使用现有`rgb_siglip.py`的channels_last包装，不退回父类旧入口。[L10] |
| OVR的pooling使用插值后`mask>0` | 0/1mask的插值正值会扩散边界；padding错误会把背景算入区域 | 使用有符号±1掩码、负值padding，并记录特征网格有效支持。[X02] |
| OVR公开分类返回softmax概率 | 再把概率当余弦做softmax，会重现来源表达不一致问题 | 在视觉投影与单位文本原型处导出未缩放余弦，移除logit_scale/void/COAT后处理。[X02/X03] |
| OVR checkpoint可能同时有`backbone`与`frozen_backbone` | 误加载冻结分支会得到貌似成功、实则未测试区域微调的结果 | 明确权重键映射，核对活动权重；原始冻结骨干作为独立对照。[X04] |
| 官方OVR安装说明仍有旧`fcclip/...`路径 | 盲目照抄可能花时间编译完全不使用的分割模块 | 优先最小OpenCLIP区域链，保留许可归属，不建设panoptic训练环境。[X09] |
| SAM3处理器数组尺寸读法与`masks_logits`命名容易误导 | HWC输入可能尺寸解释错误，已sigmoid结果可能被再sigmoid | 固定PIL RGB，记录概率值域；每类清空提示状态但复用图像编码。[X07] |

其中800/1333的OVR resize是**本包明示的外部区域适配约定**，并非声称从作者所有配置中读到了同一默认值。原始FC与OVR两路保持完全一致，防止把预处理差异当成微调收益。

## 三、每个模块的实际工作与对照

| 家族 | 开发任务 | 必须的对照 | 结果应回答什么 |
|---|---|---|---|
| E01 | 回收Q保留视图，增加原均值/单位均值/平滑几何中位数 | 原面积融合、RAW_EQ、UNIT_EQ、GMED | 坏视图污染是否能用稳健方向读出减轻？还是仅去掉面积/改变范数有效？ |
| E02 | 原union、纯global、SAM2.1视觉框修复三种识别mask | 同S2、同bbox、同3视图、同权重 | 真正有效的是区域变干净，还是额外SAM并无价值？ |
| C0 | S2-L静态来源换成SO400M图文对 | 同原始六crop与静态请求 | 普通模型容量是否已经比复杂模块更划算？ |
| E03 | 提取ConvNeXt-L区域分支，接作者OVR权重 | 相同冻结预训练骨干、相同外部global mask和文本模板 | 效果来自架构/pooling，还是区域微调确有增益？ |
| E04 | 用SAM3在候选类别中提供空间支持 | A7短名单原分数、空间支持直接读出、固定50/50结合 | 定位证据能否减少共同语义误判？ |

每个新来源都生成DIRECT与A7两种输出。单独较差但融合有用也属于可保留的实验事实；不增加第四票、不用复杂门控包装坏输出。

E01不用新增视觉推理。E02改的是识别时的黑背景遮罩，不是3D mask。E03是外部mask区域分支适配，不是完整OVRCOAT或FC-CLIP复现。E04的“无检出”不证明物体不存在，其证据是当前指定区域上的相对空间支持。

## 六、关于资源与不过度测试

本轮可能新增SAM2、SO400M、匹配OpenCLIP/OVR和SAM3的官方权重及必要依赖；这是用户同意测试新模型后的明确授权范围，不延续旧任务“禁止所有新模型”的限制。

不重装已经能工作的原生/S2环境；新worker隔离。授权范围外不下载模型或数据。权重门控无法访问时，仅对应叶任务记录阻塞，不绕过许可，也不拿随机初始化或别的模型充数。

每个静态编码器最多3840个目标—视图请求；SAM3最多7680个目标—视图—候选类别对。图像编码按帧复用，完全相同的模型/图像/mask/crop操作才可复用。记录逻辑与物理成本，不能把缓存命中说成方法免费。OVR不用无关分割头，避免为其编译不需要的CUDA模块。

只做九类直接相关的小检查和每个新适配器的一次真实输入检查；没有测试数量指标。禁止重跑旧560行、34/8/6矩阵、全仓动态CROVE回归、重复压力测试或旧16,430文件审计。主要验收证据是真实预测和官方指标。

已审核：首批/后备范围、真实接口与新接口区别、模型/分数/遮罩约定、8个来源变体与19个新方法计数、温度拟合权限、CAL/Replica顺序、单次组合边界、官方池化与固定排名区别、逻辑/物理成本、失败路径及GitHub发布。
