# 源码审核、范围修正与任务拆解

日期：2026-09-30。本文是执行方案，不是新实验报告。

## 1. 这轮真正要改变什么

此前最佳AP候选D2依赖原生实例几何，三路齐全时为0.25N＋0.25Q＋0.5FC。当前参考提交是 `1ce806b22c63943843300006b5b1034ec9e1cb0b`，上游为 `f8f7bcd0ca8228f6b8b4064f2e29dcee3a502424`。本次将干预前移到二维—深度融合、局部物体到全局实例的关联，以及进入建图的时序mask；保留现有N/Q/FC模型、标量和D2规则。

历史Replica官方池化：N0为8.685272/27.261462，FC等权为10.491020/30.013672，D2为11.763120/29.716355（APall/mIoU，%）。这些仅是历史参考，不是保证新包装器应通过调参“对齐”的目标。

## 2. 重新读代码后，必须修正的细节

| 事实 | 原路线的风险 | 最终执行版处理 |
|---|---|---|
| 实际原生捕获是 `inst_association=4` | 旧参数help只列到3，容易误以为不改成3就不走图 | 保持4；它同时更新计数关联和片段图 |
| mode4的普通`getInstanceLabel`采用label/class/instance计数；mode3才直接读图组件 | 只改`SegGraph`不一定改变实际raycast owner | 明确全局超点、计数owner、图组件三个命名空间，干预真实调用链 |
| 原生已经按相同当前二维实例汇总片段后插入图 | 把“分组片段”重新当作全新实现 | 新关联决策前移到超点匹配，并贯穿后续计数和alias合并 |
| `ratio_greater_than_min`被计算却未参与接受条件 | 新方法优于基线可能只是加了一个本可直接启用的门控 | 加入BB05_RATIO_GATE简单对照；不默默修改全部基线 |
| 深度融合循环会修改残余面积与mask | 顺序敏感尚未被量化 | 先测真实顺序差异，再做不可变原区域上的同时划分 |
| 100像素门槛作用于原深度片段，不是每个切出的交集 | 新实现可能顺手再次删小片段 | 维持原作用位置，不夹带B02实验 |
| 原native surface readout以三角形首顶点颜色赋值，并有语义观测资格筛选 | 换成数值owner导出可能被误算为主干收益 | 官方主表保留旧导出语义；raw数值owner另外用于几何诊断 |
| 原评测器持有一个native anchor及其投影 | 新map复用旧anchor会评到旧形状 | 每个map建立自己的anchor/GeometryIdentity/投影/共享mask目录 |
| FC worker主要保存逐请求池化向量，不保证保存整图dense feature | 改mask后仍宣称零新增推理 | 仅在实际dense缓存存在且身份一致时re-pool，否则真实推理并计成本 |
| SAM2视频接口的结束帧包含端点 | `max_frame_num_to_track=1`并非仅当前帧 | 固定传0，逐当前帧使用；禁止提前加入未来种子 |

对应源码与检索范围见 `SOURCE_EVIDENCE.md`。这些发现说明了应检查/对照什么，不代表已经实测证明它们造成了多少掉点。

## 3. 首轮范围：7个主干配置＋最多1个组合

| 配置 | 目的 | 唯一主干变化 | 对照 |
|---|---|---|---|
| BB00_NATIVE | 建立新执行框架的真实参照 | 无科学变化 | 历史原生/D2桥接 |
| BB01_SYNC | 减少顺序相关的片段扩张与归属改变 | 同时处理二维候选与深度片段 | 原顺序、反序诊断、原阈值 |
| BB05_RATIO_GATE | 排除简单门控即可解决问题的解释 | 启用原有比例条件 | 原native greedy |
| BB05_FORWARD | 验证物体级关联及其真实执行耦合 | 正向方向性匹配＋候选/alias约束 | native及ratio |
| BB05_BIDIR | 验证反向覆盖是否提供独立价值 | 同一匹配机制＋双向交集 | FORWARD |
| BB03_SAM2_RAW | 检验时序mask进入建图能否减碎片 | 同帧计划上的SAM2传播 | CropFormer |
| BB03_SAM2_GEOM | 检验历史RGB-D是否能抑制传播漂移 | 共享RAW预测＋定向可见支持检验 | SAM2_RAW |
| BBX_COMPOSE | 检验一个前端与一个结构改进能否互补 | 仅一个固定组合 | 两个组成项与BB00 |

B03使用已有SAM2大模型与其视频预测器。五个有效计划帧为一块，块首使用CropFormer种子；当前未被RAW传播覆盖的CropFormer候选仍可作为新物体进入地图。不做额外语义检测、不使用未来提示、不额外加入计划外视频帧。

B04完整OVRCOAT本轮明确延期。现有OVR实验只验证过区域算子与识别骨干，不能把完整分割器当成已经接好的替代模型。SAM3历史上存在官方权限阻塞，也不应在这轮反复尝试它。B02、B06—B12仍是后续研究清单；没有必要一次性安装11套论文系统。

## 4. 代码接入的因果路径

```text
原始RGB-D、位姿、相机与固定帧表
    → 原CropFormer / 同帧SAM2新实例图
    → 原深度融合 / BB01同时融合
    → 进入当前帧之前读取旧地图支持
    → 超点候选与物体级关联（native / ratio / forward / bidir）
    → 真实mode4计数更新＋原片段图＋兼容alias融合
    → TSDF与当前owner投影
    → 新地图自己的native请求、Q_GAIN状态与FC区域请求
    → 原生读出 / FC等权 / D2
    → 该地图自己的GT投影与官方池化
```

B05不能只写一张Python匹配表。它必须影响候选重算、计数关联和alias合并；否则可能“提出了新匹配”，最后地图仍被旧规则改回去。反过来，也不能把所有深度片段都硬塞进一个superpoint，丢掉OVI的内部结构。

## 5. 数据与选模安排

四个开发场景固定为 scene0056_00、scene0534_00、scene0445_00、scene0626_00，全部都是历史曝光数据。每个配置先在这四场景完成原完整200槽位计划，不截取有利子序列。将原来的两场CAL扩成四场开发选择，目的是减少一次两场排序的偶然性，不将这些场景重新包装成独立验证。

每张map只生成一次，通过同一批真实语义证据得到NATIVE_READOUT、FC_EQ、D2三个读出。网络、Q小头和来源温度均冻结。原CAL用原留一场标量，其余场景用原final标量；不因几何变化重拟合温度。

选择一个结构候选、一个前端候选。两者只要确有最终raw几何/实例干预且都完整，即使单项暂时没有净收益，也允许一次组合，检验互补。随后冻结研究提名与至多四个配置（BB00、两候选、组合），再迁移到Replica八场景。不得看完Replica再重新选参数、换组合或改写提名。

以D2开发集官方池化选模：APall在最高值0.05个百分点内，比较mIoU的0.10个百分点带宽，再比较AP50的0.10个百分点带宽，最后按单独部署该方法所需图像编码量、可归属的单独运行时间估计、模块复杂度和ID决胜。这些带宽是事先声明的工程偏好，不是统计显著性判断。

最多64个成功map-scene任务，192条主排名下的scene/readout记录。第二排名、诊断、重试与身份复用不算新的独立实验。实际数量随组合和可执行性减少，必须按真实账本统计。

## 6. 防止“指标变了但没有主干贡献”

主表保持已经厘清的官方当前类别排名和整数据集池化；APall使用发布版实际0.50—0.90向量，AP25独立。改变坐标/行顺序后按同样Open3D float32最近邻和严格5厘米阈值重建投影，不沿用旧索引。

几何诊断使用raw数值owner，不受“这个物体是否已有两次语义观测”筛选影响，报告类别无关一对一召回、每GT最佳IoU、碎片与误合并、表面精度/完整度。同时记录raw物体→可导出物体→N/Q/FC可用物体的覆盖变化。

若只有类别、来源可用性或面积排名改变，而raw形状/划分不改善，只能说明系统输出变化，不能直接宣称更强建图主干。若新的二维mask改善但最终图没有改变，要报告该干预被哪一层吸收，不能用模型自身质量代替地图效果。

## 7. 成本与工程边界

这轮不承诺零GPU。原始输入和已验证公共缓存尽量复用；新mask需要新的区域特征，新主干需要新的观测谱系。RAW/GEOM共享SAM输出，三个最终读出共享N/Q/FC源证据，避免重复计算。

只编译新任务的原生目标，使用独立补丁工作树与二进制；不覆盖native-v10、不升级旧实验环境、不杀其他GPU任务。对同一故障只做一次定向修复重试，再记录真实阻塞。没有独立场景不阻塞这轮历史回归；但无法运行必需模型也不能将该条件标为COMPLETE。

验证限于约12个新定向测试、一个真实短调用链和本来就要跑的完整BB00桥接场景。禁止全仓199项旧测试重跑、16k历史文件反复哈希、通用安全fuzz和泛化的“零风险”流程。必要的数据/缓存身份检查不能删，但按实际输入一次性核验。

Codex应提交新代码、原生patch、规格、小结果、选模和四份报告：RESULTS、HANDOFF、SELECTION、CLAIMS，并实际普通push到 `research/ovimap-backbone-wave1-v1`。完整本地HEAD和远端SHA一致后，才在外部回执中写PUSH_VERIFIED。部署继续N0_UNCHANGED。

本执行包已读取并绑定真实源码及报告，但没有访问服务器共享存储、没有编译实际C++、没有运行新的SAM/建图或场景评测。随包审查只验证指令一致性和小型参考算子，不能据此认定新方法有效。

预期收益方向是更好的完整实例与更少误关联；是否涨点以及涨多少，必须由本轮真实比较回答。若ratio门控或简单前端已胜过双向匹配，应保留简单方案，而不是为复杂设计补写没有证据的机制解释。

成本排序不以缓存命中后的零开销取巧：RAW与GEOM都计入它们需要的SAM公共阶段。实际本轮物理计算与每种方法独立所需计算分别记录。
